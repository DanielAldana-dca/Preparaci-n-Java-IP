# 🎓 Preparación para Exámenes de Suficiencia - Introducción a la Programación II (IP II)

> **Objetivo:** Este repositorio de notas es una guía completa de estudio para los **exámenes de suficiencia de Introducción a la Programación II (IP II)**. Además, sirve como material autodidacta para **aprender Programación Orientada a Objetos (POO) con Java** desde cero, paso a paso.

---

## 📖 ¿Qué encontrarás aquí?

Este material está organizado en **8 días de estudio intensivo**, cada uno cubriendo un tema fundamental de POO. Cada día incluye:

- 🎯 **Objetivos claros** de aprendizaje.
- 📚 **Teoría detallada** con analogías y explicaciones profundas.
- 📐 **Ejemplos de código** mínimos para ilustrar conceptos clave.
- 📊 **Tablas comparativas** y resúmenes visuales.
- 💡 **Buenas prácticas** y **errores comunes**.
- ✅ **Checklist de aprendizaje** para autoevaluarte.
- 🔗 **Enlaces a otros días** y referencias bibliográficas.

Los archivos están escritos en **Markdown** y optimizados para **Obsidian**, usando enlaces `[[...]]` para navegar entre días.

---

## 🗓️ Distribución de los 8 Días

| Día | Tema | Contenido principal |
|:---:|:---|:---|
| **1** | Clases y Objetos | Encapsulamiento, atributos, métodos, constructores |
| **2** | Relaciones entre Clases | Asociación, agregación, composición, GRASP |
| **3** | Herencia | `extends`, `super`, `protected`, `@Override`, casting |
| **4** | Polimorfismo | Ligadura dinámica, métodos abstractos, sobrescritura |
| **5** | Interfaces | Contratos, herencia múltiple, `implements`, `default` |
| **6** | Genericidad | Clases genéricas, `Lista<T>`, wrappers, tipos acotados |
| **7** | Excepciones | `try-catch-finally`, `throw`, `throws`, excepciones propias |
| **8** | Ficheros | Texto, binario, serialización, `Serializable` |

## 🎯 ¿Para quién es este material?

- **Estudiantes de IP II** que se preparan para los exámenes de suficiencia.
- **Autodidactas** que quieren aprender POO con Java desde cero.
- **Programadores de otros lenguajes** (C#, Python, C++) que quieren migrar a Java.
- **Estudiantes de la UCI** que cursan la asignatura Introducción a la Programación II.

---

## 🚀 ¿Cómo usar este material?

### 📌 Para los exámenes de suficiencia

1. **Estudia un día por sesión**: dedica 2-3 horas a cada tema.
2. **Lee la teoría completa** antes de mirar los ejemplos.
3. **Reescribe los ejemplos** en tu IDE (VSCode, IntelliJ, NetBeans).
4. **Resuelve los ejercicios** propuestos (si los hay) o inventa los tuyos.
5. **Marca el checklist** al final del día para verificar que dominas el tema.
6. **Repasa los días anteriores** antes de avanzar.

### 📌 Para aprender POO desde cero

1. **Sigue el orden de los días** (1 → 8); cada uno construye sobre el anterior.
2. **No saltes la teoría**: las analogías y explicaciones son clave.
3. **Practica con código real**: crea tus propias clases y objetos.
4. **Consulta las tablas resumen** cuando olvides algo.
5. **Vuelve al Cheatsheet** antes de cada sesión de práctica.

## 🧠 Metodología de Estudio Recomendada

### Fase 1: Lectura activa (30-40 min)
- Lee la teoría del día.
- Subraya conceptos clave.
- Anota dudas en un cuaderno o en Obsidian.

### Fase 2: Práctica guiada (40-60 min)
- Copia y ejecuta los ejemplos de código.
- Modifícalos para experimentar.
- Verifica la salida esperada.

### Fase 3: Práctica autónoma (60-90 min)
- Resuelve los ejercicios propuestos.
- Inventa tus propios ejemplos.
- Intenta explicar el concepto con tus palabras.

### Fase 4: Consolidación (20-30 min)
- Marca el checklist de aprendizaje.
- Revisa los errores comunes.
- Repasa el Cheatsheet.

## 🎓 Consejos para el Examen de Suficiencia

1. **Domina los conceptos, no memorices código**: entiende el "por qué" de cada cosa.
2. **Practica escribir código a mano**: en el examen puede que no tengas IDE.
3. **Aprende a leer diagramas UML**: muchos problemas se modelan primero.
4. **Estudia los exámenes anteriores**: los patrones se repiten.
5. **Gestiona tu tiempo**: en el examen, lee todo antes de empezar a escribir.
6. **No te saltes las excepciones**: son muy comunes en los exámenes.
7. **Domina `Lista<T>`**: es la base de casi todos los ejercicios.
8. **Practica con proyectos reales**: los ejercicios de examen son mini-sistemas.
